# DVA-1 v2 — Chief Orchestration Wrapper

This is the Chief-facing contract around `v2.md` (the verbatim rubric). It
never restates or replaces the rubric — it only says what Chief must feed
in, what it must get back, and how the gate/advancement logic works. See
`v2.legacy-operator-instructions.md` for what was superseded.

## Input contract

- `destinationId`, `destinationName` (required identity)
- No prior-stage artifact required — DVA-1 is the entry point (D0/D1 in `destinationHubLifecycle.ts`'s stage order already screen for `manageableGeography`/`tourismIdentity`/etc. before DVA-1 runs).

## Expected structured output (`DVA1Artifact`, `destinationHubLifecycle.ts`)

- `score` (0–100, the rubric's Overall Opportunity Score)
- `recommendationText` (the rubric's Section 12 Recommendation sentence)
- `currentStrategyFit` — one of `FITS_CURRENT_STRATEGY` / `STRONG_BUT_LATER_STAGE` / `WEAK_STRATEGIC_FIT`, from the rubric's Section 13 classification. **Required** — this is a separate dimension from `score`, never inferred from it.

## Gate fields / automatic advancement rule

`evaluateDVA1Gate()`:

| score tier (exact rubric thresholds) | currentStrategyFit | outcome |
|---|---|---|
| ELITE (90–100) or EXCELLENT (80–89) or BORDERLINE (65–79) | `FITS_CURRENT_STRATEGY` | **auto-advance** to DVA-2 — no Jerry gate |
| ELITE or EXCELLENT or BORDERLINE | `STRONG_BUT_LATER_STAGE` | hold — `NEEDS_JERRY` (founder judgment on timing/sequencing, not a re-ask of something already answered) |
| any tier | `WEAK_STRATEGIC_FIT` | archive — no DVA-2 proposed, no Jerry needed (routine) |
| ARCHIVE (below 65) | any | archive — no DVA-2 proposed, no Jerry needed |

This directly implements the Phase 2G task's explicit instruction: "Do not
advance solely on raw score if the methodology explicitly identifies the
destination as later-stage / strategically premature," and "Routine
qualified progression should not require Jerry just to move a file to the
next stage."

## Artifact identity requirement

`DVA1Artifact.destinationId` must match the destination the execution was
scoped to (`SpecialistExecutionRequest.destinationId`) — enforced by the
existing hard-isolation check in `executor.ts`'s `assertExecutionIdentity`.

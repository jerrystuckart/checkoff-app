DVA-2 always takes a completed, Jerry-approved DVA-1 as its input — `validateDva2Input()` in
`destinationHubLifecycle.ts` hard-rejects a DVA-2 artifact whose `consumedDva1ArtifactRef` does
not match the DVA-1 artifact Chief actually has on file for that destination, and whose
`destinationId` doesn't match.

Output shape (retrieved): `GREEN | YELLOW | RED`.

- **GREEN** → eligible to advance toward DAP. Still requires Jerry's explicit approval before DAP
  actually starts (`routeDVA2Recommendation()`), same "never auto-advance" discipline as DVA-1.
- **YELLOW** → if the artifact names `evidenceGaps`, more research first (not necessarily Jerry —
  `WAITING`, `requiresJerry: false`); once gaps are resolved (or none were ever named), Jerry
  reviews.
- **RED** → route by the artifact's own `suggestedDisposition` (`HOLD | WAVE_2 | DECLINE`).
  Absent a stated disposition, default to `HOLD` — the safest, reversible option. **Never
  auto-DECLINE**; a destination is not permanently discarded solely because timing is wrong today.
